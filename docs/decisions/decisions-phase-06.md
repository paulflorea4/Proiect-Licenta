## 6.1b — `pydantic-settings` config class

- **New dependency `pydantic-settings` (gate, approved by the human).** Offered against a hand-written class over `os.environ`, which would not read `ai-service/.env` itself. It brings `python-dotenv` as its only new package. Added without a version bound in `pyproject.toml`, like `fastapi` and `uvicorn` (`uv add` wrote `>=2.16.1`, removed to match); `uv.lock` pins 2.16.1 and 1.2.4.
- **Only `AI_SERVICE_TOKEN` is required now.** The row says the service refuses to start without it. `.env.example` says the API key is only needed once the service calls the real API (6.2a), and the model is not used before then either, so both are optional (`None`) until 6.2a, which will refuse to build the Gemini provider without them. The model has no default anywhere, as the root `CLAUDE.md` asks.
- **Blank is empty.** A token of spaces is refused like an empty one; a blank Gemini value is `None`. A token is not trimmed or otherwise changed (the backend compares it as it is), and no minimum length is enforced: none is written anywhere, and `.env.example` already asks for a long random value. Left to the human if wanted.
- **"Refuses to start" is the app's `lifespan`,** which calls `get_settings()` before serving: uvicorn prints the validation error (the variable's name and "must not be empty", never a value) and exits with code 3 (checked by hand with a real uvicorn start). Reading the settings at import time instead would have made `import ai_service.main` fail in every test without a token.
- **The token and the API key are `SecretStr`,** so the settings print as `**********` in a log line, a `repr` or a dump (the root `CLAUDE.md`: the token is never logged).
- **The `.env` path is found from the package's own location** (`DEFAULT_ENV_FILE`), not the working directory, so the service reads `ai-service/.env` however it is started. Real environment variables win over the file (pydantic-settings' order); unknown variables in the file are ignored, so one shared file with other services' variables would not stop it.
- **Tests never read the developer's own `.env`:** `tests/conftest.py` sets `config.ENV_FILE` to `None`, a test token and no Gemini values for every test, and clears the `get_settings` cache around each. A test that wants a file writes one in `tmp_path`.
- **Tests (+17, ai-service 1 -> 18; backend 2226 and frontend 3 unchanged and passing):** the three values from the environment and from a file; the environment wins; the default file is `ai-service/.env`; the settings are exactly the variables of `.env.example`; unknown variables ignored; a missing, empty or blank token refused (also the unfilled copy of `.env.example`); the app does not start without a token and answers `/health` with one; Gemini values optional, blank = unset; no secret in `str`, `repr` or a dump; settings read once.
- **Mutation-checked, each failing at least one test:** no blank check (3 failures); the token a plain `str` (4); the settings not read at startup (1); the env file never read (1).
- **Existing warning, not from this change:** pytest reports Starlette's `StarletteDeprecationWarning` about `httpx` in its test client (it was there before, with 1 test). Not acted on.

## 6.1c — Bearer-token authentication

- **"At the router level" = `protected_router()`.** It returns an `APIRouter` whose `dependencies` hold `require_bearer_token`, so every endpoint declared on it is checked and none can opt out. Every module that adds endpoints (`POST /feedback` in 6.5a first) creates its router with it and `main.py` includes it. A dependency on the whole app was the other way, but it would have had to skip `/health` by path inside the check; with routers, `/health` simply is not on one.
- **What makes "can't forget" true is the guard test,** as for the backend's matrices: `test_every_route_of_the_app_but_health_requires_the_token` lists every route of the real app and fails for any but `GET /health` that lacks the check (an endpoint put straight on `app`, a router built with `APIRouter()`, a mounted app). A positive control shows the guard does see such routes.
- **FastAPI's `/docs`, `/redoc`, `/openapi.json` (and `/docs/oauth2-redirect`) are switched off.** They were served without a token, and the row says every route except `GET /health` requires one. Protecting them instead would mean replacing FastAPI's built-in routes with our own; the service is internal (only the backend calls it) and its contract is its pydantic models and tests, so they are off. Turning them back on behind the token is a small change if the human wants them.
- **The comparison:** `hmac.compare_digest` on the UTF-8 bytes of the sent and the configured token. On `str` it raises `TypeError` for non-ASCII characters, which would make such a header a 500; as bytes it is a 401 (tested by sending raw UTF-8). It runs whatever the scheme, so a wrong scheme takes the same path. Only the token's length can still show in the timing, which `compare_digest` does not hide; with a long random token that tells nothing useful.
- **One refusal for everything:** a missing header, an empty one, another scheme, a token without a scheme, extra spaces, a near miss and a wrong token all get the same 401 body `{"detail": "Not authenticated"}` and `WWW-Authenticate: Bearer` (RFC 6750), and the body never holds what was sent. The scheme is matched ignoring case (RFC 7235: scheme names are case-insensitive); the token exactly. `{"detail": ...}` is FastAPI's own error shape: the backend's `{status, code, message}` is its public contract, and this service's only caller is the backend's own client (Phase 7), which will map any non-2xx to its own error.
- **Nothing is logged** by the check, so the token cannot be.
- **The token is read through `get_settings()` on each request** (cached since 6.1b), so a test's `monkeypatch` of `AI_SERVICE_TOKEN` is seen once the cache is cleared, as the conftest does.
- **There is no protected endpoint yet,** so the tests build a probe app with one endpoint on a router from `protected_router()`: the same function, check and settings the real endpoints will use.
- **Tests (+26, ai-service 18 -> 44; backend 2226 and frontend 3 unchanged and passing):**
  - the right token reaches the endpoint, with the scheme in any case;
  - 15 wrong headers are each a 401 with the fixed body and `WWW-Authenticate`: none, empty, scheme only, scheme and space, wrong token, Basic, another scheme, token without scheme, two spaces, trailing space, one character more at either end, upper case, half the token, non-ASCII;
  - every refusal is byte-identical and shows no token;
  - `compare_digest` is what compares (spied, with the exact bytes), and the configured token is the one checked;
  - `/health` answers 200 without a header, with a wrong one and with a malformed one;
  - every route of the app but `/health` is checked, the documentation routes are 404, and the guard sees an unchecked route (positive control).
- **Mutation-checked, each failing at least one test:** the router without the check (17 failures); the scheme not checked (3); `==` instead of `compare_digest` (1); the documentation routes served again (2); `str` instead of bytes (2: the non-ASCII header becomes a 500).
- Also checked by hand on a real uvicorn: `/health` 200 without a token, `/docs` and `/openapi.json` 404, the token not in the log.

## 6.2a — LLM provider interface + Gemini over httpx

- **Gate resolved by the human:** `GEMINI_API_KEY` and `GEMINI_MODEL` were already in `ai-service/.env` (checked only for being non-empty; the key was never read or printed). Two more questions were put and answered:
  - **`httpx` moved from the `dev` group to the runtime dependencies** (a gate: it was not installed in production). Same version as before (0.28.1, already locked for the test client), so nothing new is downloaded. The alternative offered was the standard library's `urllib`.
  - **Real Gemini calls were allowed** ("a few calls"). Three were made: the live test (HTTP 404, see below), one listing of the models the key may use (only names printed), and the live test again (passed, 4 characters of text).
- **The model in `.env` did not exist.** `gemini-3-flash` answered 404; the key's model list has `gemini-3-flash-preview` and `gemini-3.5-flash`, not that name. The human chose `gemini-3.5-flash` (a fixed, non-preview version, so the thesis's experiments are not moved by a model change), and only the `GEMINI_MODEL` line of their `.env` was changed. Nothing in the repository names a model.
- **The API's shape was taken from Google's documentation at the time of writing,** not from memory: `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`, body `contents[].parts[].text`, text at `candidates[].content.parts[].text`, `promptFeedback.blockReason` when the prompt is blocked (then no candidates). The documentation's own examples put the key in the URL (`?key=`); its API-key page shows the **`x-goog-api-key` header**, which is what this uses, so the key never appears in a URL (proxies and access logs record URLs).
- **The interface is an `ABC` with one method, `generate(prompt) -> str`,** the row's "prompt in, text out". Synchronous: the endpoint (6.5a) will be a plain `def`, which FastAPI runs on a worker thread, so a blocking call does not stall the event loop; and the service makes one call per request.
- **Errors are typed, and the type says what 6.3c can do about it:** `LlmUnavailable` (no answer: timeout, connection failure, any non-2xx status), `LlmBadResponse` (an answer without usable text: not JSON, blocked, no candidate, empty or blank text), `LlmNotConfigured` (key or model missing, or a model name that is not a plain name). Their messages are fixed text. **None ever holds the key, the prompt (it will hold student code) or Gemini's answer** (an error body can echo the request). The original `httpx` error is chained for the log: its text holds at most the URL, and the key is in a header, which a traceback never prints.
- **No retry here.** 6.3c's row is "retry once, then a clean error"; this row only reports.
- **The model name must be a plain name** (letters, digits, `.`, `_`, `-`, starting with a letter or digit), because it goes into the URL's path: `models/x`, `x?key=1`, `../x`, `x:generateContent` and the like are refused at configuration rather than producing a strange URL. The model is not given a default anywhere, and `test_no_model_name_is_written_in_the_code` greps `src/` for Gemini model names.
- **Timeouts are named placeholders,** connect 5 s and read 30 s (write and pool get 30 s too, so no phase is unbounded). **Phase 7's backend client must allow for them**: its read timeout on the call to this service has to exceed this read timeout, or the backend gives up while Gemini is still answering.
- **Only the first candidate is used,** its text parts joined (one prompt asks for one answer; Gemini returns one candidate unless asked for more). Non-text parts are skipped.
- **The provider is not wired into any endpoint:** 6.2b proves it with one hardcoded prompt, and 6.5a wires `POST /feedback`.
- **Tests (+46 and 1 opt-in, ai-service 44 -> 90; backend 2226 and frontend 3 unchanged and passing):**
  - the request: one `POST` to the exact URL, the exact JSON body, the key only in the header and nowhere in the URL, the prompt byte for byte (quotes, backslashes, tabs, non-ASCII, emoji), the timeouts bounded and equal to the constants;
  - the answer: the text, the first candidate's parts joined and other candidates ignored, the class an `LlmProvider`;
  - no usable answer: seven HTTP statuses each `LlmUnavailable` with only the status in the message; four transport failures (connect and read timeouts, connection refused, protocol error); twelve shapes without usable text and a non-JSON answer each `LlmBadResponse`; no message ever holds the key or the prompt;
  - configuration: key or model missing, eight bad model names, an empty key, the configured key and model used, the key not in the provider's `repr`, no model name in the source;
  - `test_the_real_gemini_api_answers_a_prompt`, skipped unless `RUN_LIVE_GEMINI=1`; it prints only the length of the answer.
- **Mutation-checked, each failing at least one test:** the key in the URL (4 failures); no HTTP status check (7); the last candidate instead of the first (1); any model name accepted (8); the answer's text in the error message (7); no read timeout (1, after tightening the timeout test: it first compared the client with the constant, so a constant of `None` passed).

## 6.2b — Prove it with one hardcoded prompt

- **The form was the human's choice** (nothing in the spec says what "prove it" means, a choice with no default). Offered: a module and a command (chosen), a temporary protected `POST /feedback`, or only a live test. Chosen because the prompt then lives where 6.3b's builder replaces it (`HARDCODED_PROMPT` in `feedback.py`, used by `generate_feedback`), and no HTTP contract is published that 6.3a/6.5a would have to reshape.
- **The prompt is a made-up case with no student's data:** a tutor's hint for a program that prints the product instead of the sum, with "Do not write the corrected code". It is one constant, as the row says; nothing is parameterised.
- **`generate_feedback` takes an `LlmProvider`,** not a `GeminiProvider`, so it is tested with a fake and so 6.3b/6.5a keep the provider seam of 6.2a.
- **The command** (`uv run python -m ai_service.feedback`) builds the provider from the settings (`ai-service/.env`), prints the answer to stdout and exits 0. When it is not configured (no Gemini key or model, or no token) or the call fails, it prints one line to stderr (`Not configured: ...` / `No feedback: ...`) and exits 1, never a traceback; the provider is closed either way. The messages are the fixed texts of 6.2a's errors, so no key or prompt is printed.
- **Proven against the real API** (calls allowed by the human at 6.2a): the first two runs got HTTP 503 from Gemini (the model was briefly unavailable on Google's side; the command reported it in one line, as designed), the third, a minute later, printed a hint that names the faulty operator and gives no code. The 503s are the case 6.3c's retry is for.
- **Tests (+9 and 1 opt-in, ai-service 90 -> 99; backend 2226 and frontend 3 unchanged and passing):** the hardcoded prompt is sent once and the answer returned; the prompt asks for a hint and forbids the corrected code; provider errors are not hidden; the command prints the answer and closes the provider, reports a failed call in one stderr line and closes the provider, reports missing Gemini settings and a missing token; `python -m ai_service.feedback` runs as a real process (with empty Gemini values in its environment, which win over the developer's `.env`, so it never reaches the network); an opt-in live test (`RUN_LIVE_GEMINI=1`).
- **Mutation-checked, each failing at least one test:** the provider never closed (2 failures); a failed call not caught (1); a configuration failure not caught (3); the failure printed to stdout (1).

## 6.3a — Pydantic models for `POST /feedback`

- **camelCase on the wire (gate, the human's choice):** `assignmentDescription`, `publicTests`, `hintLevel`. Every other JSON in the platform is camelCase, so the backend's DTO (7.1a) needs no naming annotation. Python keeps snake_case attributes through pydantic's `to_camel` alias generator. **Only the camelCase names are accepted** (`validate_by_alias=True`, `validate_by_name=False`): accepting both would make two spellings of one contract, and with unknown fields forbidden a snake_case key is refused like any other.
- **Hidden tests are hidden by the shape, as the row asks:** `HiddenTestResult` has exactly one field, `passed`. No name either (not even the masked `Hidden test N` of 5.5a): the model needs only how many passed and failed, and a free-text name field is a field a hidden test's real name could be put into. Their order is the run order the backend sends.
- **Every model forbids undeclared fields** (`extra="forbid"`). The point is the hidden tests: a backend that sends `{"passed": false, "input": ...}` gets a 422 instead of the input quietly being ignored today and used by a later prompt change. It also catches a backend DTO that drifts from this one (a misspelt or extra field fails loudly).
- **What a public test carries:** name, input, expected output, status, actual output, stderr ("public test results with detail"). Not its weight, position or runtime: none helps a hint, and the rubric is not shown to students (3.4a). `actualOutput` and `stderr` are optional, because a compile error has no actual output (5.3b).
- **`compilerOutput` at the top level,** the same text the student sees (5.5a). It is there because a compile error's message otherwise travels only in the stderr of public tests, and an assignment whose tests are all hidden would send none.
- **`TestOutcome` is copied from the backend,** and `test_the_outcomes_are_exactly_the_backends` reads `backend/.../sandbox/TestOutcome.java` (comments stripped) and compares the names in order, so the two cannot drift. The ai-service CI checks out the whole repository, so the file is there.
- **Strict where a coercion would hide a bug:** `hintLevel` is a strict integer from 1 to 3. A `Literal[1, 2, 3]` was tried first, and the tests showed it accepts `true`, because Python's `True == 1`. `passed` is a strict boolean, so `"true"`, `1` or `null` are refused. The three texts must be non-empty and are kept exactly as sent (no stripping): code is whitespace-sensitive.
- **The response is `{hint}`,** the row's "hint text". Nothing else is needed by 7.2a, which stores it with the level it asked for.
- **The models are frozen,** so a request read once cannot be changed on its way to the prompt.
- **Not decided here: size limits.** Nothing bounds the length of the code (128 KiB in the backend), a test's texts (up to 100000 characters) or outputs (up to 1 MiB each) in a request, and all of it can end up in a prompt, which costs tokens. Either 7.1b (what the backend sends) or 6.3b (what the prompt includes) should cut it; noted in `docs/suggestions.md`.
- **Tests (+54, ai-service 99 -> 153; backend 2226 and frontend 3 unchanged and passing):**
  - a valid request read field by field, from a dict and from JSON text; text kept exactly; a compile error with `compilerOutput` and no actual output; optional outputs; no tests of either kind; each level; every outcome; the outcomes equal the backend's;
  - a hidden test is only `passed`; seven attempts to add a field to it are refused; no model but the public test has a content field; unknown top-level and public-test fields refused;
  - every required field, empty texts, nine bad levels (0, 4, -1, 1.5, "1", null, true), five non-booleans, an unknown outcome, snake_case names, a change after reading;
  - the response is `{"hint": ...}` and refuses an empty hint; the request is written back with exactly the camelCase keys the backend's DTO must have.
- **Mutation-checked, each failing at least one test:** unknown fields ignored (13 failures); an `input` field on the hidden test (4); a lax boolean (4); snake_case accepted (1); level 4 allowed (1); empty code allowed (1); an outcome missing (1).
