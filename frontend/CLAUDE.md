# frontend/CLAUDE.md

React + TypeScript on Vite, npm. Project-wide rules (gates, defaults, Git safety, PR flow) are in the root `CLAUDE.md`; this file only holds what is specific to `/frontend`.

## Commands (run from `/frontend`)

- Install: `npm ci` (or `npm install` when changing dependencies)
- Dev server: `npm run dev`
- Tests: `npm test` (Vitest, single run)
- Lint: `npm run lint` (ESLint, flat config in `eslint.config.js`; chosen over the template's oxlint at 0.5c). Don't add another linter on your own.
- Format: `npm run format` (Prettier, writes) / `npm run format:check` (verify only). Config in `.prettierrc.json` (no semicolons, single quotes, `endOfLine: "auto"` so CRLF checkouts on Windows pass).
- Build: `npm run build` (runs `tsc -b`, then `vite build`)
- Dev server runs at `http://localhost:5173`, the origin already listed in `CORS_ALLOWED_ORIGINS` in `backend/.env.example`.

## Layout and test setup

- Source is in `src/`. Confirmed current at 8.1a (Node 24, install, build, tests, lint, format and the dev server checked); 8.1a also ran `npm audit fix` (lockfile only, the human's approval): `npm audit --omit=dev` is clean, and 13 moderate dev-only findings in the ESLint chain remain with no non-downgrade fix (`docs/suggestions.md`). A lockfile change is a dependency change: ask first.
- Routing (8.1b): `react-router` ^8.5.1 (the human's approval), declarative mode. `main.tsx` wraps `App` in `BrowserRouter`; **`App.tsx` holds only the `AuthProvider` (8.3b) and the `<Routes>`**, so tests render `App` inside a `MemoryRouter initialEntries={[path]}` (see `App.test.tsx`'s `renderAt`) and get the whole app; **since the provider asks `GET /auth/me` on load, every test that renders `App` calls `stubApi(fetchMock)` from `src/test/api.ts`** (it answers `/auth/me`, signed out unless given another `me`, and passes every other call to `fetchMock`, so a page test sees only its own requests). Routes: `/` (8.4a: the guest landing page; a signed-in user is sent to their role's home), `/signin`, `/signup`, `/courses` (9.1a: a teacher's own courses with their enrollment codes and the create form; an admin sees every course, no form; the student's view is 9.1b's), `/admin/users` (8.5b: the admin user list, `AdminUsersPage`) and `*` (not-found page with a link home). **Role homes (8.4a) are `homeOf(role)` in `src/auth/authContext.ts`, the one place they are written**: student and teacher `/courses`, admin `/admin/users`. `/` and a sign-in without a return path go there. **Guards (8.3c, `src/auth/routeGuards.tsx`) are layout routes: wrap routes in `<Route element={<ProtectedRoute />}>` (signed in) or `<Route element={<RoleRoute roles={['TEACHER', 'ADMIN']} />}>` (signed in with one of the roles, listed explicitly: no role implies another, as on the backend).** While `GET /auth/me` has not answered, both show "Checking your sign-in…" and never redirect. A signed-out user is sent to `/signin` with `state.from` = path + query, and signing in returns there (`returnPathOf` accepts only a path of this app: not `//host`, another site, or `/signin` itself). A signed-in user without the role goes to `/`. `/courses` is behind `ProtectedRoute`, `/admin/users` behind `RoleRoute roles={['ADMIN']}` (8.4a). **Lists (8.5b, first: `AdminUsersPage`):** a paginated endpoint answers `PageResponse<T>` (`src/api/types.ts`, `page` 0-based); the page keeps its page in the URL 1-based (`?page=2` is the API's `page=1`; anything that is not a whole number from 1 is the first page; page 1 has no parameter), with Previous / Next and "Page X of Y (N users)": **since 9.1a the shared `src/components/Pager.tsx` (give it the noun, singular and plural) and `pagination.ts`'s `pageNumberOf`**, used by `AdminUsersPage` and `CoursesPage`. Data is fetched in an effect with an `AbortController`, and **state is set only from the request's callbacks** (react-hooks lint forbids a synchronous `setState` in an effect): the result records the page it is for and "loading" is derived when that is not the URL's page. These are conveniences: the backend decides every access (2.5a). Import everything from `react-router` (v8 has no `react-router-dom`). Deep links need the server to answer every path with `index.html`: Vite's dev server does; the production host must too (Phase 16, `docs/suggestions.md`).
- Vitest runs on jsdom with Testing Library. `src/test/setup.ts` is the setup file and registers `cleanup` itself.
- Vitest globals are off: import `describe`, `it` and `expect` explicitly in every test file.
- Tests live next to the code (`src/App.test.tsx`).
- TypeScript is strict about unused code and syntax (`tsconfig.app.json`): `noUnusedLocals`/`noUnusedParameters`, `verbatimModuleSyntax` (use `import type` for type-only imports) and `erasableSyntaxOnly` (no enums or parameter properties). `npm run build` fails on violations; ESLint (`*.ts`/`*.tsx` only) and Prettier run separately.

## Conventions

- Pages (8.1b, the first real components): one per route in `src/pages/`, file `<Name>Page.tsx`, a plain `function` with `export default` (as `App`); its root is `<main>` with exactly one `<h1>` (tests find pages by that heading). Shared components, state and styling conventions are still unset: the tasks that introduce them decide. **Set by 8.5a: every route sits inside the `AppShell` layout route (`src/components/AppShell.tsx`: `Header`, then the page). The header has the app's name (a link to `/`, not an `<h1>`: each page keeps exactly one), the menu for the role (`MENU` in `Header.tsx`, the one place it is written: student and teacher Courses, admin Users and Courses; a guest gets Sign in and Sign up; nothing while `/auth/me` is open), "Signed in as … (Role)" and a Sign out button. Sign-out does not navigate: on a guarded page the guard sends the user to `/signin`, on a public page they stay. A page's own links share names with the menu ("Sign in", "Sign up"), so a test looks them up inside `screen.getByRole('main')` (or `banner` for the header).** **Set by 8.3b:** shared components live in `src/components/` (`TextField`, the labelled input with its linked error, a `<textarea>` when given `rows` (9.1a); `CopyButton` (9.1a), a "Copy" button with an accessible name saying what it copies, announcing "Copied" or, when the browser refuses the clipboard, to copy by hand, in a `role="status"` next to it; `CreateCourseForm` (9.1a); `fieldErrors.ts`'s `fieldErrorsOf`, a `VALIDATION_FAILED` mapped onto a form's fields). **Auth state** is React context, no library: `src/auth/authContext.ts` (`User`, `AuthState` = `loading` / `signedIn` with the user / `signedOut`, `useAuth()`, which throws outside the provider) and `src/auth/AuthProvider.tsx` (asks `GET /auth/me` once on load: 200 = signed in, anything else = signed out; `signedIn(user)` records a signin's answer and abandons a check still open; `signOut()` posts `/auth/signout`, then signed out, and rethrows a failure keeping the state). The two are separate files because a module that exports a component must export only components (react-refresh lint). Role checks made from this state are a convenience; the backend decides.
- Forms (8.3a, `SignUpPage`): `noValidate` on the `<form>`, so the page's own checks (mirroring the backend's limits, as named constants, only to answer sooner) and the backend's are shown the same way: the message under the field, linked by `aria-describedby`, with `aria-invalid`; tests read it with `toHaveAccessibleDescription`. A backend `VALIDATION_FAILED` is mapped onto its fields by `fieldErrors[].field` (the request record's component name); a code that belongs to one field (`EMAIL_ALREADY_USED`) goes on that field; anything else is one `role="alert"` message above the button (`ApiError.message`). The submit button is disabled while the request runs. Signup has no role field (signup always creates a student); after it succeeds the page shows a `role="status"` confirmation with a link to `/signin` (signup returns no token).
- Only `VITE_`-prefixed variables are exposed to client code, and everything in them ends up in the browser bundle: never put a secret there. Local values go in `.env.local`. The only variable so far is `VITE_API_BASE_URL` (the Spring Boot base URL, default `http://localhost:8080`, no trailing slash — see `frontend/.env.example`).
- The frontend talks only to the Spring Boot API, never to the Python service (`docs/project-specifications.md`, Architecture).
- **API calls (8.2a) go through `src/api/client.ts`, never raw `fetch`:** `api.get/post/put/patch/delete<T>(path, ...)` or `apiRequest<T>(path, options)`. The path starts with one `/` and is relative to `VITE_API_BASE_URL` (read on every call; unset or blank throws a configuration `Error` before any request, so copy `.env.example` to `.env.local`). Plain `fetch`, no axios (that would be a dependency). A body is sent as JSON, a `FormData` as multipart; the result is the parsed JSON, `undefined` for an empty body (204). Every failure is an `ApiError` (`status`, `code`, `message`, `fieldErrors`): `code` is the backend's `ErrorCode` name (branch on it with `isApiError(e, 'CODE')`, never on `message`), or the client's own `NETWORK_ERROR` (no response, `status` 0) or `UNEXPECTED_RESPONSE` (a body not in the 2.6a shape, such as Tomcat's HTML 400 page, or an unreadable 2xx body). `message` is fixed text, safe to show. An aborted call (`signal`) rethrows the abort error unchanged. **Auth is the backend's `httpOnly` cookie (8.2b-8.2f, the human's decision at 8.3b): the frontend never sees or stores the token.** Every call is `credentials: 'include'` (the API is another origin, so without it the browser neither sends the cookie nor keeps the one signin sets), and every non-GET call carries `X-Requested-With: XMLHttpRequest` (`CSRF_HEADER`, set after the caller's headers so it cannot be dropped; the backend refuses a cookie-authenticated write without it, 403 `CSRF_HEADER_MISSING`). GETs do not send it (it would force a CORS preflight). Who is signed in comes from `GET /auth/me`; sign out with `POST /auth/signout`. Tests stub `fetch` and the variable with `vi.stubGlobal` / `vi.stubEnv` (`client.test.ts`).
- Tests are part of the commit that adds the code, and all tests of all three projects must pass before a task counts as finished (root `CLAUDE.md`, Workflow).
- New dependencies are a gate — ask before adding one.
