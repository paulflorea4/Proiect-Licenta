| 7.1a | Backend `AiServiceClient` (Spring `RestClient`) calling `POST /feedback`, base URL from `AI_SERVICE_URL`, `Authorization: Bearer` header from `AI_SERVICE_TOKEN` on every call (set once as a default header on the client), explicit connect/read timeouts | Not started | Request DTO mirrors 6.3a. | 7.1b | Build the feedback request from a submission: assignment description, code, public results in full, hidden results as pass/fail only | Not started | Single mapping method, covered by 7.5a — this is the place a hidden test could leak, so keep it small and reviewable. |
| 7.2a | `POST /submissions/{id}/hints`: generate the next hint level (own submission, graded, hint level 1–3) | Not started | First call → level 1, then 2, then 3. Returns the stored hint, never regenerates an existing level (unique constraint from 1.3a). After level 3 → `409` with a clear message. Release the DB transaction before calling the AI service and save the row afterwards. Two simultaneous requests for the same level hit the unique constraint — catch it and return the existing row. |
| 7.2b | `GET /submissions/{id}/hints`: hints already received | Not started | Same role-based projection as 5.5a. |
| 7.2c | Eligibility rule: hints only when the submission is `GRADED` and at least one test did not pass | Not started | All tests passed → `409` ("nothing to improve"). Judged on test results, not on the total: a lost `MANUAL` mark on a fully passing submission does not mean the code is wrong. Improvement hints for passing code arrive with static analysis in Phase 13. |
| 7.3a | Failure handling: AI service down, timeout, or error → `503` with a clear message; the submission and its grade are untouched | Not started | The deterministic grade must never depend on the AI. Retry/backoff is Phase 16's job, not here. |
| 7.4a | Track hints used: count exposed on the submission DTO (student and teacher views) | Not started | Derived from `ai_feedback` rows, no separate counter. Hints never affect the score. |
| 7.4b | `POST /submissions/{id}/hints/{level}/report`: the student flags one of their own hints as wrong or unhelpful, with an optional reason | Not started | Idempotent — reporting twice keeps the first timestamp. Reported flags appear in the teacher's submission view (5.5b projection). Gives the thesis a measured hint-error rate from real use; hints are never altered or deleted by a report. |
