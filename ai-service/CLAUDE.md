# ai-service/CLAUDE.md

Python FastAPI service, managed with `uv` (build backend: `hatchling`). Project-wide rules (gates, defaults, Git safety, PR flow) are in the root `CLAUDE.md`; this file only holds what is specific to `/ai-service`.

## Commands (run from `/ai-service`)
- Install dependencies: `uv sync`
- Tests: `uv run pytest` (test paths are configured in `pyproject.toml`). The one test that calls the real Gemini API is skipped unless `RUN_LIVE_GEMINI=1` (`RUN_LIVE_GEMINI=1 uv run pytest -s -k real_gemini`); it reads the developer's own `ai-service/.env`. CI never sets it (no key there).
- Run: `uv run uvicorn ai_service.main:app --reload` (uvicorn's default port 8000 matches `AI_SERVICE_URL` in `backend/.env.example`)
- Lint: `uv run ruff check .` (add `--fix` for auto-fixable findings). Format: `uv run black .` (`--check` to verify only). Both run in CI (`.github/workflows/ai-service-ci.yml`); config is in `pyproject.toml`. ruff only lints — black is the formatter, so don't enable `ruff format`.
- Always go through `uv run` — don't call a global `python` or `pytest`.
- `uv.lock` is committed and CI runs `uv sync --locked`: after any dependency change, commit the updated lock file or CI fails.
- `requires-python` is `>=3.12`, and CI runs on 3.12. A newer local interpreter works, but don't rely on features newer than 3.12.

## Layout
- `src/ai_service/` — the package (`main.py` holds the FastAPI `app`; only `GET /health` exists so far).
- `tests/` — pytest tests, using FastAPI's `TestClient`. `httpx` is a runtime dependency since 6.2a (the Gemini client), approved by the human; the test client uses the same package.
- Settings (6.1b, `config.py`): `Settings` (`pydantic-settings`, added at 6.1b with the human's approval; it brings `python-dotenv`) reads exactly the variables of `ai-service/.env.example` from the environment and from `ai-service/.env` (`DEFAULT_ENV_FILE`, found from the package's location, so it works whatever the working directory; real environment variables win; unknown variables are ignored; no database settings). **`AI_SERVICE_TOKEN` is required**: missing, empty or blank stops the service at startup (the app's `lifespan` calls `get_settings()`; uvicorn prints the variable's name, never a value). `GEMINI_API_KEY` and `GEMINI_MODEL` are optional until 6.2a (blank = `None`; the model has no default anywhere). The token and the API key are `SecretStr`, so printing or logging the settings shows `**********`. Use `get_settings()` (read once, cached), never `Settings()` directly. Never commit `ai-service/.env`.
- Tests: `tests/conftest.py` gives every test the same settings whatever the developer's own `.env` holds (`config.ENV_FILE` set to `None`, a test token, no Gemini values, cache cleared around each test); change them with `monkeypatch` (the `test_token` fixture holds the token). `with TestClient(app)` runs the startup (and so the settings check); a plain `TestClient(app)` does not.
- Authentication (6.1c, `auth.py`): **every endpoint except `GET /health` requires `Authorization: Bearer <AI_SERVICE_TOKEN>`**. The check, `require_bearer_token`, is attached to routers, never to single endpoints: **create every new endpoint on a router made by `protected_router()`** and include it in `main.py`. The scheme is matched ignoring case, the token exactly, with `hmac.compare_digest` on bytes (a non-ASCII header is a 401, not a 500); missing, malformed and wrong all get the same 401 `{"detail": "Not authenticated"}` with `WWW-Authenticate: Bearer`, never echoing what was sent. FastAPI's `/docs`, `/redoc` and `/openapi.json` are switched off (they would be open). `tests/test_auth.py::test_every_route_of_the_app_but_health_requires_the_token` fails when any route of the app other than `GET /health` lacks the check (an endpoint added straight on `app`, a router made another way).
- LLM providers (6.2a, `llm.py`): **code against `LlmProvider` (`generate(prompt) -> str`), never against Gemini directly**, so providers can be compared (thesis). `GeminiProvider` posts to `{GEMINI_BASE_URL}/models/{model}:generateContent` with the key in the **`x-goog-api-key` header, never the URL**, `contents: [{role: user, parts: [{text: prompt}]}]`, and returns the first candidate's text parts joined. Build it with `gemini_from_settings(get_settings())`: key and model must both be set (else `LlmNotConfigured`); the model must be a plain name (letters, digits, `.`, `_`, `-`). Timeouts: `CONNECT_TIMEOUT_SECONDS` 5, `READ_TIMEOUT_SECONDS` 30 (placeholders; the backend's own timeout on its call here must allow for them, Phase 7). Errors are typed and their messages fixed text, **never the key, the prompt or Gemini's answer**: `LlmUnavailable` (timeout, connection failure, any non-2xx: `Gemini answered HTTP <status>`, plus Gemini's `error.status` word in parentheses since 6.3c, e.g. `(UNAVAILABLE)`, **only if it is one plain uppercase word**; its `status_code` attribute is the HTTP status, `None` for a timeout or failed connection), `LlmBadResponse` (not JSON, prompt blocked, no candidate, no or blank text). No retry in the provider: 6.3c retries in `feedback.py`. Tests fake Gemini with `httpx.MockTransport` (pass an `httpx.Client` to the constructor). `test_no_model_name_is_written_in_the_code` fails if a Gemini model name appears in `src/`.
- Feedback (6.2b, `feedback.py`; since 6.3b and 6.3c): `generate_feedback(provider, request) -> str` sends `build_prompt(request)` and returns the hint read by `parse_hint`: the answer must be exactly `{"hint": "<non-blank>"}` (validated with `FeedbackResponse`, so no other key; a Markdown code fence around the whole answer is unwrapped; the hint is stripped), anything else is `LlmBadResponse` with a fixed message that never quotes the answer. **At most `MAX_ATTEMPTS` (2) calls per hint:** a bad or empty answer, or an `LlmUnavailable` whose `status_code` is in `RETRYABLE_STATUS_CODES` (429, 500, 502, 503, 504), gets one more try with the same prompt; a timeout, a connection failure, any other status and `LlmNotConfigured` are raised at once (a second 30 s wait would outlast the backend's timeout). After two failures the last error is raised. **A hint that leaks (6.4a, `find_leak`) is regenerated within the same two attempts; when the last attempt leaks, `SAFE_HINT` is returned, never the leak** (a leak then a failure raises the failure). `uv run python -m ai_service.feedback [1|2|3]` runs the made-up `SAMPLE_REQUEST` (no student data) at that hint level against the real Gemini API with `ai-service/.env` and prints the answer (exit 1 with a one-line reason on stderr if not configured or the call fails; 2 for a bad argument). `POST /feedback` comes in 6.5a.
- Prompts (6.3b, `prompts.py`): **`build_prompt(request)` is a pure function** (no clock, file or network; same request, same prompt). Order: the rules, the level's instructions (`LEVEL_INSTRUCTIONS[1..3]`: 1 nudge, no mistake/place/fix, no code; 2 where and what kind, no fix, no code; 3 the fault and the reasoning the fix needs, **stopping short of the exact change** (no operator, value, condition or line to write instead: the human's decision at 6.3c), at most one illustrative snippet of `MAX_SNIPPET_LINES` lines on a different example, never the corrected program), then the data, then a reminder. **Every outside text is a fenced block** labelled `UNTRUSTED` (the student's code, the compiler message, the actual output and stderr of a public test: all written or printed by the student's program) or `from the teacher` (description, a public test's input and expected output). **The fence is a line of backticks one longer than the longest run of backticks in any block (at least 3)**, so nothing in a block can contain it or end the block early, and no character of the code is changed. Hidden tests appear only as `Hidden tests: k of n passed.` The model is asked for `{"hint": "..."}`. `MAX_SNIPPET_LINES` (5, placeholder) is the constant 6.4a's leak guard enforces. **Any new text that reaches the prompt goes in a block, and anything the student's program produced is `UNTRUSTED`.**
- Leak guard (6.4a, `leak_guard.py`): **`find_leak(hint, request) -> Leak | None` is a pure function**. Code in a hint = every non-blank line of a fenced block (``` or ~~~, closed only by a fence of the same character at least as long; an unclosed fence runs to the end), a line of prose that reads as a statement (ends in `;`/`{`/`}`, starts with a lowercase keyword and has code punctuation, an assignment, a whole-line call) and an inline span that does. **A line copied unchanged from the student's code (whitespace ignored) is not new code.** Refused, in order: new code lines beyond `MAX_CODE_LINES` (`{1: 0, 2: 0, 3: MAX_SNIPPET_LINES}`) → `TOO_MUCH_CODE`; new code that reads input and prints, or declares an entry point → `COMPLETE_PROGRAM` (one list of markers for all languages, no branch per language); a new line at least `LINE_SIMILARITY` (0.8, placeholder) like one of the student's → `EDITED_STUDENT_LINE` (the fix, which level 3 must stop short of). `SAFE_HINT` is the generic hint, safe at every level. Heuristics: prose naming the fix in words is not caught (only the prompt forbids it).
- The `POST /feedback` contract (6.3a, `schemas.py`; the backend's DTO in 7.1a mirrors it): **camelCase on the wire** (the human's choice, like all the platform's JSON), snake_case attributes in Python, and only the camelCase names are accepted (`validate_by_name=False`). `FeedbackRequest {assignmentDescription, language, code, compilerOutput?, publicTests: [PublicTestResult], hiddenTests: [HiddenTestResult], hintLevel}` → `FeedbackResponse {hint}`. `PublicTestResult {name, input, expectedOutput, status, actualOutput?, stderr?}`; **`HiddenTestResult` is `{passed}` and nothing else**. Every model has `extra="forbid"`: a field it does not declare is refused (422), so hidden test data cannot reach a prompt by being added to a request. `TestOutcome` mirrors the backend's enum; `test_the_outcomes_are_exactly_the_backends` reads `TestOutcome.java` and fails if they drift. `hintLevel` is a strict integer 1-3 (`true`, `1.5`, `"1"` refused); `passed` a strict boolean; the three texts non-empty and kept exactly as sent. **A new field that can hold a test's content belongs on `PublicTestResult` only**, and `test_no_field_anywhere_can_carry_hidden_test_data` checks that.
- Code style is enforced by ruff + black (type hints on function signatures, as in the existing code); the layout grows with the tasks that add modules — don't pre-create empty packages.

## Conventions
- This service never connects to the database (root `CLAUDE.md`, Table ownership) and never executes student code (`docs/project-specifications.md`, Architecture). Everything it needs arrives in the request body.
- Every endpoint except `GET /health` requires the bearer token (root `CLAUDE.md`, Defaults; 6.1c, see Layout).
- Tests are part of the commit that adds the code, and all tests of all three projects must pass before a task counts as finished (root `CLAUDE.md`, Workflow).
- Rules fixed in the root `CLAUDE.md` Defaults that apply here once the code exists:
  - Gemini is called through a provider interface, and the model name comes from `GEMINI_MODEL` — never hardcode it.
  - Student-supplied text (code, comments, open answers) is untrusted data in every prompt: clearly delimited and quoted, never instructions. Hidden test inputs and expected outputs are never put in a prompt.
  - The bearer token is compared in constant time and never logged. The service is reachable only by the backend over a private network.
  - Plagiarism constants (k-gram size, window size, similarity threshold `0.70`) are named constants — don't inline them or tune them.
- New dependencies are a gate — ask before adding one.
